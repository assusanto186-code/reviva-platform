# Reviva Brand System

Version: 1.0

Status: Draft

Owner: Reviva Engineering Team

---

# Purpose

This document defines the visual language of Reviva.

Every interface, component, page, and future application must follow this document.

The goal is consistency, maintainability, and long-term scalability.

---

# Brand Personality

Reviva should always feel:

- Professional
- Trustworthy
- Calm
- Intelligent
- Premium

If a design decision conflicts with these principles, choose the option that better reflects the brand personality.

---

# Brand Promise

Reviva is an AI Front Desk Employee for Med Spas.

Our interface should inspire confidence rather than excitement.

Trust is more important than visual effects.

---

# Design Principles

## 1. Calm

Avoid unnecessary visual noise.

Whitespace is part of the design.

---

## 2. Premium

Minimal elements.

Maximum clarity.

---

## 3. Human

Technology should feel approachable.

Never intimidating.

---

## 4. Consistent

The same action should always look the same.

Buttons, forms, colors, and spacing should never behave differently without reason.

---

## 5. Functional

Every UI element must have a purpose.

Decorative elements should be minimized.

---

# Color Philosophy

Reviva uses semantic colors instead of implementation colors.

Preferred naming:

- Primary
- Secondary
- Background
- Surface
- Foreground
- Success
- Warning
- Error
- Muted

Avoid naming components using color values such as:

- Emerald
- Blue
- Red

Components should depend on meaning, not implementation.

---

# Typography

Typography should prioritize readability.

Hierarchy:

H1

H2

H3

Body

Caption

Avoid unnecessary font sizes.

---

# Spacing

Spacing should follow a consistent scale.

Never use arbitrary spacing.

---

# Radius

Rounded corners communicate friendliness.

Reviva prefers medium to large radius.

Avoid sharp corners unless required.

---

# Shadows

Shadows should be subtle.

Avoid heavy floating effects.

---

# Icons

Icons should support understanding.

Never replace text with icons alone.

---

# Accessibility

Accessibility is not optional.

Every component should support:

- Keyboard navigation
- Visible focus state
- Proper contrast
- Screen readers where applicable

---

# Engineering Rule

Design decisions must be documented before becoming standards.

Components should implement the Brand System rather than defining it.

---

End of Document.
